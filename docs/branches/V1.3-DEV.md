# GSOS Observer V1.3-DEV — Development Charter

- **Branch:** `GSOS-Observer-V1.3-DEV`
- **Target version:** 1.3.0
- **Parent release:** 1.2.0 (frozen, see `docs/RELEASES.md`)
- **Owner:** GSOS Observer engineering

## Mission

Retire the highest-priority technical debt inherited from V1, improve
maintainability of the existing codebase, and prepare the architecture
for future modules — **without** shipping any new user-facing feature.

## Priorities

### Priority 1 — Resolve Technical Debt

| ID | Item | Target outcome |
| -- | ---- | -------------- |
| TD-001 | Authentication System | Replace localStorage demo auth with a real session-based system backed by Lovable Cloud (Supabase Auth). Add sign-in / sign-out / session restore, protected routes, and a `user_roles` table with `has_role()` per the platform pattern. No role-gated UI yet — just the plumbing. |
| TD-002 | Telemetry & Monitoring | Introduce a minimal, provider-agnostic telemetry layer (event + error capture interface) with a no-op default and a documented hook for a future real backend. Wire error boundary + server function errors through it. No third-party SaaS in this sprint. |
| TD-003 | Searchable Arabic PDF | Replace the image fallback with a searchable Arabic PDF using a shaping-capable pipeline (evaluate `pdf-lib` + `HarfBuzz`/`fontkit`, or embed an Arabic-capable TTF into jsPDF with a shaping step). Deliverable: AR export is text-selectable and copy-pasteable. |

### Priority 2 — Maintainability

- Break down `src/routes/dashboard.tsx` (TD-004) into smaller,
  single-responsibility modules (panel, dialogs, export, AI review).
- Extract PDF export pipeline into `src/lib/pdf/` with a typed API.
- Do **not** refactor the analysis engine (`src/lib/indicators.ts`,
  `src/lib/analysis/*`). Engine behavior is frozen for V1.3.

### Priority 3 — Architectural Preparation (no implementation)

- ADR-0004: authentication and session model.
- ADR-0005: telemetry interface and provider strategy.
- ADR-0006: PDF pipeline v2 (Arabic shaping).
- Draft folder layout / module boundaries for the History & Archive
  module (Sprint 3) and Administration (Sprint 4) — documentation only.

## Explicitly out of scope for V1.3

- New AI features or expansion of AI Review.
- New dashboard layout.
- New indicators.
- Any change to analysis logic or scoring thresholds.

These are scheduled **after** all TD-001, TD-002, TD-003 exit criteria
are met.

## Exit criteria for v1.3.0

1. TD-001, TD-002, TD-003 marked **Closed** in `docs/TECH_DEBT.md`
   with linked ADRs and tests.
2. Lint clean, strict TS build clean, unit tests green, and manual
   test report re-run against the new auth flow.
3. `CHANGELOG.md` has a complete `[1.3.0]` entry.
4. `docs/PRODUCTION_READINESS.md` re-issued for v1.3.0.
